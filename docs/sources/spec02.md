# spec02调度服务设计

OnTime Dispatch / Coordinating Time-Critical Material Delivery: A UAV–AGV Service Concept  
v1.0｜2026-09-30｜P07 / PolyU SSD  
**Proposed extension**：本次服务设计提案；未经用户研究或部署验证。演示数据统一标为 **Illustrative data**。

## 1. 问题、使用者和服务边界

调度员需要知道任务要求是否完整、候选安排依据什么计算、哪些任务无法分配，以及改变输入后哪些决定已过时。服务目标是支持检查、理解、确认模拟执行和异常恢复；算法找到候选方案不等于任务已成功交付。

| 项目 | 本次假设／范围 | 证据／状态 |
| --- | --- | --- |
| 场景 | 一个仓库向多个生产工位配送；有限的UAV、AGV，具备不同能力及多趟需求 | 原研究：spec01 S01–S08；FY01 s16–19；paper01 PDF p1 |
| 主要使用者 | 有基本车间物流知识的调度员，检查需求和车辆资源，并承担模拟方案批准责任 | 新增使用者假设P；没有访谈证明其实际工作方式 |
| 需求方 | 工位物料需求提出者，负责目的工位、载荷和时间要求的准确性；实际原型可由调度员代录 | P；不默认已有需求方账户或真实通知渠道 |
| 规划程序 | 接收不可变输入快照，生成候选安排，由独立校核器计算时序及可行性；保留未分配原因 | P接口设计；原方法仅支持两阶段研究概念，spec01 K01–K11仍待源码 |
| 模拟设备 | 依据当前批准方案推进确定性的离散事件模拟；显示模拟时间、状态和事件 | P；没有设备控制、实时遥测或真实接单 |
| 目标 | 每项任务有归属或原因；批准有明确范围；输入变化可追踪；异常不自动批准新方案 | P；本轮定义目标，没有完成效果测量 |
| 研究经历 | Peiming为英文会议摘要第一作者，2025-07-19在宜昌报告共同研究 | 保留spec01 S15–S16；不推定全套代码作者 |

本阶段制作服务规格和低保真界面，不实现原调度源码，不替代spec01待核事项。后续可以使用单独的演示规划器，但必须披露规则、独立校核及其与原方法的区别。

## 3. 两条服务旅程

所有旅程为本次推演，没有观察、访谈或已完成用户测试记录。

### 3.1 任务正常完成（演示正常场景仅含T01–T03）

| 阶段 | 需求方／调度员行为 | 系统信息交接及反馈 | 风险、责任与下一步 |
| --- | --- | --- | --- |
| 提出需求 | 需求方提供目的地、载荷、时间窗；调度员录入或导入 | 显示单位、arrival规则、输入版本及缺失字段 | 需求方负责要求真实性；调度员校对，缺字段不能规划 |
| 检查 | 在Task Review检查任务和设备可用性 | 校验规则、逐行错误；有效输入不等于可行分配 | 调度员修正输入，规划程序只做格式及规则校验 |
| 理解候选 | Generate plan→Plan Review；查看三个任务及计算时间 | Suggested；逐行ETA、服务结束、返仓、时间窗检查；路线及时间线 | 程序负责计算及校核；调度员检查具体安排和约束 |
| 确认 | Approve plan，查看批准范围及再次确认 | Approved绑定版本与plan ID；没有自动开始模拟 | 调度员负责批准选择；仍是模拟方案 |
| 模拟执行 | Start simulation→Execution Monitor | 当前批准快照、模拟时钟、Waiting／Travelling／Serving／Delivered；返仓事件 | 模拟器负责事件顺序；不是物理交付或实时遥测 |
| 结束 | 查看任务完成和所有设备返仓 | All tasks completed in simulation；结束时刻、任务明细与事件记录 | 只有全部纳入任务Delivered且返仓完成才显示全完成；不声称真实成效 |

正常演示中三个任务时间均由spec03算例规则复算。四页SVG另外展示含T04的Partial场景，用于暴露未分配任务；部分执行结束文案为“Assigned tasks completed; 1 task remains unassigned”。两种结果不能混用。

### 3.2 设备不可用（UAV-01变为Unavailable）

| 阶段 | 调度员动作 | 系统与信息交接 | 失败点及责任 |
| --- | --- | --- | --- |
| 事件 | 在Execution Monitor模拟UAV-01不可用 | 记录设备变更、模拟时刻及原因；暂停全部模拟 | 本次采用全局暂停降低同时执行复杂度；并非实地调度规则 |
| 失效 | 打开Exception Handling | 增加快照版本；旧Suggested／Approved失效；历史批准仍可查看 | 程序立即阻止旧计划启动／恢复；已完成事件保留 |
| 核对影响 | 查看T01原安排、设备可用性、未完成任务及检查点 | 受影响任务Interrupted／Needs replan；可用车辆与候选约束检查 | 调度员判断修改资源、保留未分配或重新规划 |
| 重新规划 | Replan remaining tasks | 新建议基于可用设备、检查点和已完成任务集合计算；不能复用旧ETA | 程序负责结果；无可行节点时保留任务和原因 |
| 再确认 | 转Plan Review，比较新旧安排与未分配任务 | 新方案Suggested；Partial确认勾选未分配清单；Approve partial plan | 调度员决定是否接受可执行部分；没有自动继承批准 |
| 恢复 | 批准后Resume simulation | 使用新批准快照；保留旧事件审计；已完成任务不重派 | 模拟器校验批准仍有效；零可执行任务留在异常页，不显示成功 |

SVG设备异常取09:00、出发前事件；异常优先于同刻出发，因此没有途中位置。运行中异常的本次简化处理为回滚未完成行程到最近完成的仓库检查点，保留已完成任务；界面必须说明“Simulation rollback”，模拟时钟不倒退，不声称真实返仓。若以后加入实地控制，需另行设计安全停车、载荷位置和恢复策略。

### 3.3 时间要求变化的处理分支

需求方提出新窗口→调度员编辑并保存→快照增版本、旧建议／批准失效→若运行则暂停→Exception Handling显示旧／新窗口和任务影响→重新规划→Plan Review重新确认→恢复模拟。已Delivered任务的历史要求及交付事件不可覆盖；如需新增配送，创建新任务。放宽窗口同样失效，因为可能影响排序和其他任务时序。

## 4. 服务蓝图

| 阶段 | 需求方：前台／责任 | 调度员：前台／责任 | 规划程序：后台／责任 | 模拟设备：后台／责任 | 信息交接、失败点及归属 |
| --- | --- | --- | --- | --- | --- |
| 收集 | 提供工位、载荷、窗口；负责业务要求 | 录入、单位核对、查看错误 | 保存草稿并校验；禁止缺失或反向窗口 | 尚不执行 | Task draft→validated snapshot；业务缺失由需求方补，格式错误由调度员修 |
| 资源检查 | 确认时间要求可否调整 | 设置模拟设备可用性、能力、规则 | 冻结资源与规则版本；生成快照 | 提供模拟配置，不冒充遥测 | availability／capacity／travel matrix；未知规则阻止规划 |
| 规划 | 无默认在线操作 | Generate plan，理解候选 | 规划＋独立时间／载荷／返仓校核；逐项保留未分配 | 不接收Suggested | snapshot→candidate＋validation；超限为约束原因，崩溃为计算错误 |
| 批准 | 可由调度员记录需求方意见；无真实消息发送 | 检查影响；完整／部分方案分别批准 | 再校验版本及可行性；记录批准范围与操作者标签 | 尚不推进 | candidate ID＋snapshot→approval；过时则拒绝，责任在调度员选择／系统防护 |
| 执行 | 查看需求模拟结果可由调度员展示 | Start／Pause／Resume；查看事件 | 限定批准任务集，持久化模拟检查点 | 依据计划推进到达、服务完成、返仓事件 | approval→sim run；缺批准不得启动；设备负责的是模拟状态而非真实设备 |
| 异常 | 提出窗口变更 | 标设备不可用／改窗口；核对新旧、重新规划 | 使旧批准失效；重算剩余任务，保留已完成事实 | 全局暂停；未完成行程按检查点回滚策略标记 | event→new snapshot；不得静默丢任务、倒写历史或自动批准 |
| 收尾 | 核对需求是否全部完成 | 查看Delivered与Unassigned，记录后续处理 | 检查纳入任务全集及完成／未分配数量 | 所有已执行行程返仓后结束 | 全部完成／部分完成／未运行／故障须区别；不能用“success”掩盖未服务任务 |

前台线：调度员只操作四页界面；需求方通过任务信息交接进入服务。后台线：规划、校核、版本、批准和模拟事件。信息交接均为原型内部数据及可导出记录，不包含真实邮件、消息或外部系统承诺。
