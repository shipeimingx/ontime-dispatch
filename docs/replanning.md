# 仓库检查点后的设备不可用：2026 新增扩展

`src/ontime/replan.py` 是本次新增机制，原材料未定义此异常恢复算法。它生成候选计划，不自动执行，不等于人工批准。`approval_status=not_approved`、`requires_human_approval=true`、`execution_started=false` 保存在重规划及合并结果中。

## 明确的适用范围

检查点以非负整数秒表示。本演示使用基线计划的时钟模拟执行进度，**没有读取真实硬件遥测**。设备不可用事件发生在仓库，且该设备已开始的行程必须已返仓并完成仓库卸载。若故障设备仍在装载、配送、返程或卸载中，CLI 返回错误，明确不支持在途故障救援；不把它瞬移回仓库，也不将已装载任务转给其他设备。

事件优先级是本次假设：`load_start_s == checkpoint_s` 的装载尚未开始，允许取消；严格早于检查点的行程全部冻结。任务 `completion_s <= checkpoint_s` 才标为在本次模拟中完成。任务完成与设备返仓是两个不同事件。

## 分区与约束

1. **已完成任务**保留在原行程内，不再次进入搜索。状态来自基线独立重算后的完成时间。
2. **已开始行程**的输入记录（设备、任务顺序、装载时间）逐项冻结。已装载但未完成的任务及其剩余路线也保持固定；不往已经出发或开始装载的行程插入新货物。
3. **可调整任务**是其余全部任务：包括尚未装载的未来任务和原来未分配的任务。仅这些任务进入新的启发式 + GA 搜索。原先超载任务仍须通过物理约束，不能强行分配。
4. 新行程最早装载时间为 `max(检查点, 原设备可用起点, 该设备最后冻结行程的返仓+仓库卸载+周转完成时间)`。故障设备不接受新行程；已过班次的设备显式不可用，输入区间保留有效的零宽度表示。
5. 新行程 ID 独立命名，避免与历史 ID 碰撞。历史及候选未来合并后，任务必须恰好属于某一行程或未分配集合，不得重复或丢失。

`frozen_segments` 保留每段装载、行驶、工位等待 / 卸载 / 服务、返仓、仓库卸载和已计划周转的开始 / 结束秒数，并记录检查点前实际模拟的 `executed_s`、`executed_until_s`。尚未开始片段的 executed_s=0、executed_until_s=null，保留其冻结承诺；不声称未来已执行。

若冻结行程原本是该设备末趟，合并新增后续行程时，时间线会额外画出下一趟所需的仓库周转；原行程装载、访问及返仓 / 卸载时间不改变。`task-state.csv` 区分 `simulated_completed`、`locked_unfinished`、`candidate_not_approved` 与 `unassigned`，没有把全部已分配任务都标成已完成。

## 独立验证与历史可用性

`validate_replanning` 不调用启发式。它重新构造允许调整的集合，检查冻结记录、模式、检查点起点及故障后设备分配，并对剩余任务调用独立 `check_plan`。另外，用原始参数校验合并历史的载荷、返仓、时间窗、续航、同车串行及任务完整性。

历史设备的 `available=true` 不能因后来的事件改成 `false` 而抹掉此前配送。故障后的可用性通过**剩余问题**和**时间事件检查**共同约束，保存在 `replan.json` 的 validation，以及合并计划 checks / checks.csv 中。独立 `evaluate` 对原始输入只检查静态物理模型，不能单独替代重规划的时间事件验证。

剩余问题 GA 目标仅计可调整部分的运输 / 迟到罚值；冻结部分不能参与优化。不能把剩余成本与整个基线的总成本直接相减。本版没有联合最优证明、在途改道、跨设备转运、人员审批系统或执行控制。

## 本次实际演示

输入 `data/portfolio.json`，检查点 200 s，故障设备 UAV-02。基线是同次运行保存的 GA 计划。UAV-02 的假设可用起点为 240 s，事件发生时仍在仓库，尚未装载。

- 模拟已完成：T05。
- 固定的已开始行程中的未完成任务：T02、T03；行程 AGV-01-trip-1、UAV-01-trip-1、UAV-01-trip-2 保留。T02 在配送途中；T03 的装载从 182 s 开始，至 202 s 结束，检查点时装载仍在进行。
- 可调整：T01、T04、T06、T07、T08。
- 新候选仍有 T08 未分配，原因 payload_exceeded。T01、T07 改由 UAV-01 后续新行程配送；UAV-02 不再接受新行程。
- 历史物理检查、剩余计划检查及时间事件检查均通过。该候选仍未经人工批准。

这些事实读取自 `outputs/portfolio/replan/replan.json`，没有把功能演示写成用户可用性验证或真实配送完成记录。

```powershell
.\Run-OnTime-Python.cmd replan data/portfolio.json outputs/portfolio/ga/plan.json --checkpoint-s 200 --unavailable-vehicle UAV-02 --seed 2026 --output-dir outputs/replan-cli
```

输出包含剩余输入、剩余问题初始 / GA 计划、每代记录、冻结片段、独立检查及合并候选 JSON / CSV。完整一键演示用 `.\Build-Portfolio.cmd`。
