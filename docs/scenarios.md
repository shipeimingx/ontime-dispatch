# 固定种子合成算例与参数说明

所有算例均是 **Illustrative data**，2026新增演示参数，不是2025研究原数据、工厂测量、设备标定或性能基准。输入生成代码为src/ontime/generate.py；生成种子2026，生成器synthetic_v1。合成数据种子与调度平局种子是两个独立用途，本次运行二者均为2026。

## 1. 单位与生成规则

| 字段／规则 | 单位 | 2026新增演示假设 |
| --- | --- | --- |
| schema_version | 无 | 2，强制显式单位标签、速度和迟到权重 |
| depot_id、stations | ID | 一个DEPOT、八个工位，任务T01–T08各对应一个工位；不拆分 |
| coordinates_m | m | DEPOT=(0,0)；每工位x/y独立均匀整数20–180，用局部Random(2026)生成 |
| distance_m.UAV | m | 欧氏距离，保留3位小数；假设直线通行，无避障求解 |
| distance_m.AGV | m | 1.2×曼哈顿距离，保留3位小数；1.2是合成绕行系数，不证明真实障碍可行 |
| travel_time_s | s | **仅在生成数据时**ceil(距离m／该类型代表速度m/s)；完整两套矩阵保存JSON。运行核心只读矩阵，不从速度重新计算 |
| speed_m_s | m/s | UAV8、AGV1.5；同类型设备用相同代表速度，容量可不同；速度元数据不覆盖矩阵 |
| demand_kg | kg | UAV兼容任务均匀浮点1–3、保留2位；AGV专属任务均匀整数10–25；无原研究重量分类阈值 |
| eligible_types | 类型集合 | 奇数任务UAV专属，T02/T04/T06为AGV专属，T08两类都可；适配是显式输入，不由重量推断 |
| earliest_s | s | 独立均匀整数0–60，同一模拟起点后的秒数 |
| latest_s | s | T01起500，每下一个任务增加180；正常算例宽窗，实际能否安排仍以运行输出为准 |
| unload_s | s | 每任务均匀整数5–15，为工位卸货时间 |
| service_s | s | 每任务均匀整数10–30，为卸货后的服务时间，不重复包含卸货 |
| lateness_cost_per_s | penalty_unit/s | 从1、2、4等概率选择；2026罚值权重，无货币或原论文权重声明 |
| window_mode | 无 | 输入默认soft，CLI可选hard；约束服务开始（即卸货开始），早到可等待 |
| available | 布尔 | 正常算例均true；异常只改明确列出的字段 |
| capacity_kg | kg | 下表4／6／35／50；必须校核整趟预装总量 |
| trip_limit_s | s | UAV800、AGV2000；离仓到返仓，含工位等待／卸货／服务及返程，非电量百分比换算 |
| available_from/until_s | s | 下表输入范围，必须容纳仓库装货与返仓卸货；同车周转后才能下一趟 |
| load_s、depot_unload_s、turnaround_s | s | 固定每趟装货／返仓检查与卸货／下趟补给准备时间；仅需下一趟时执行周转；无真实充电模型 |
| metadata | 描述对象 | 记录种子、坐标、生成说明及异常修改，不参与调度约束 |

改变生成种子会生成其他输入，不保证产生相同覆盖结果。核心支持有向非对称／null矩阵；此合成输入恰好是对称且所有边可通行的几何示意。

## 5. 三个专门异常算例

每个异常从相同normal输入深复制，仅修改下表字段，仍保留8任务及4设备。可将正常、异常单独运行比较约束处理，不把其差异当算法性能提升。

| 输入JSON | 修改 | 触发机制 |
| --- | --- | --- |
| data/cases/overload.json | T08重量从1.92改60 kg | 超过最大容量50 kg；soft也不得违规安排或拆单 |
| data/cases/window_conflict.json | T01窗口从[5,500]改[0,1] s | UAV装货20 s后才能离仓；hard无法开始于窗口内，soft记录实际迟到及代价 |
| data/cases/unavailable.json | 两台UAV的available都改false | UAV专属任务不能偷偷改派AGV；T08两类适配可测试AGV |

实际运行记录及覆盖结果见README；JSON、CSV及独立校核保存outputs/cases/。正常输入不被预先写成“保证成功”，运行后才记录其覆盖。
